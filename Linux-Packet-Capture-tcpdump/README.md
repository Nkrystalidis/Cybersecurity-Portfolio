# Network Traffic Analysis: Packet Capture & Inspection with tcpdump

## Scenario
As a network security analyst, I was tasked with capturing and inspecting live network traffic on a Linux virtual machine. The objective was to identify active network interfaces, capture specific web traffic initiated by command-line queries, export the raw packets into a `.pcap` capture file, and analyze the packet headers and application-layer payloads using CLI utilities.

## Task
Utilize the Linux command-line packet analyzer `tcpdump` to discover interfaces, apply real-time packet filters, write captured traffic to disk, and inspect TCP/IP headers and packet contents in both human-readable and hexadecimal formats.

## Action & Commands Executed

### 1. Interface Discovery & Inspection
Identified system network interfaces and verified active link states:
* `sudo ifconfig`
* `sudo tcpdump -D`

Findings:
* Identified primary network interface `eth0` (`inet 172.17.0.2`, MTU 1460) and loopback interface `lo`.
* Listed available capture interfaces using `tcpdump -D`, confirming `eth0` as connected and operational.

### 2. Live Packet Sniffing with Protocol Filtering
Captured a limited stream of live packets with verbose header information:
* `sudo tcpdump -i eth0 -v -c5`

Findings:
* Inspected packet headers across Layer 3 and Layer 4, identifying IP IDs, TTL values (`ttl 64`, `ttl 63`), TCP sequence/acknowledgment numbers, and DNS reverse lookup queries (`PTR`).

### 3. Background Packet Capture to PCAP
Captured specific HTTP traffic generated by automated requests and saved the raw data:
* `sudo tcpdump -i eth0 -nn -c9 port 80 -w capture.pcap &`
* `curl opensource.google.com`

Findings:
* Ran `tcpdump` as a background process (`&`), capturing exactly 9 packets (`-c9`) on destination port 80 (`port 80`) without resolving hostnames or ports (`-nn`).
* Triggered web traffic using `curl opensource.google.com`, receiving an HTTP 301 response, and verified the creation of `capture.pcap`.

### 4. Deep Packet Inspection & Payload Analysis
Read and analyzed the captured packet file using verbose and hex/ASCII outputs:
* `sudo tcpdump -nn -r capture.pcap -v`
* `sudo tcpdump -nn -r capture.pcap -X`

Findings:
* Verified the complete TCP 3-way handshake (`Flags [S]`, `Flags [S.]`, `Flags [.]`) between source IP `172.17.0.2` and destination IP `74.125.195.139`.
* Extracted HTTP GET request headers from packet 4 (`GET / HTTP/1.1`, `Host: opensource.google.com`, `User-Agent: curl/7.88.1`).
* Analyzed raw hexadecimal and ASCII packet representations using the `-X` option, validating payload integrity and cleartext application data.

## Outcome
Successfully captured live network traffic from specific interfaces, filtered web requests based on port parameters, saved session data into a reusable `.pcap` capture file, and reconstructed HTTP communication flows from packet headers and hex dumps. This project demonstrates core SOC Analyst skills in command-line network packet analysis using `tcpdump`.
